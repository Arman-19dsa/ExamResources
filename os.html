Key Formulas

WT = TAT − Burst    // Waiting Time
TAT = Completion − Arrival    // Turnaround Time
RT = First CPU − Arrival    // Response Time
Avg WT = ΣWT / n    // Average Waiting Time

OS Types Compared

  • Multiprogramming – Multiple jobs in memory; max CPU use
  • Multitasking – Fast context switching; interactive feel
  • Multiprocessing – Multiple CPUs; true parallelism
  • Time-sharing – Each user gets CPU slice (RR-based)
  • Batch – No interaction; jobs queued & processed
Unit II — Sync & Deadlocks

IPC Mechanisms

MethodSpeedBest For
Shared MemoryFast (no kernel)Large data sharing
Message PassingSlower (syscall)Distributed systems
Pipes (ordinary)MediumParent-child, unidirectional
Named PipesMediumUnrelated processes, bidir

Critical Section Requirements

Mutual Exclusion Only 1 process in CS at a time
Progress Selection must happen in finite time
Bounded Wait Process waits a finite number of turns

Synchronization Tools

  • Mutex Lock – Binary; acquire()/release(); busy-wait or block
  • Semaphore – Counter; wait()/signal(); counting or binary
  • Monitor – High-level; condition variables; Java synchronized
  • test_and_set / CAS – Atomic hardware instructions for mutual exclusion
  • Memory Barrier – Prevents instruction reordering by CPU/compiler

Classic Sync Problems

  • Producer-Consumer – Bounded buffer; mutex + 2 semaphores (full/empty)
  • Reader-Writer – Multiple readers OR one writer; readers-preference
  • Dining Philosophers – 5 philosophers, 5 forks; deadlock-prone without care

Deadlock: 4 Necessary Conditions

Mutual ExclusionResource held by only one process
Hold & WaitHolding resource while waiting for more
No PreemptionResources can't be forcibly taken
Circular WaitP1→R1→P2→R2→P1 cycle

Deadlock Strategies

  • Prevention – Eliminate one of 4 conditions (e.g. ordered resource allocation)
  • Avoidance – Banker's Algorithm; keep system in safe state
  • Detection – Resource Allocation Graph; run periodically
  • Recovery – Kill processes or preempt resources
  • Aging – Gradually increase priority of waiting process → cures starvation
Unit III — Memory Management

Memory Allocation Strategies

StrategyPicksFragment Type
First FitFirst sufficient holeExternal
Best FitSmallest sufficient holeExternal (small holes)
Worst FitLargest holeExternal (large leftovers)
  • Internal Frag – Wasted space inside allocated partition
  • External Frag – Enough total free memory but not contiguous
  • Compaction – Shuffle memory to merge external fragments (costly)

Paging & Segmentation

  • Page – Fixed logical unit; Frame – Fixed physical unit (same size)
  • Page Table – Maps page number → frame number; MMU translates
  • TLB – Cache for page table; hit avoids full table lookup
  • Segment – Variable-size logical unit (code, stack, heap)
  • Virtual Memory – Execute process larger than physical RAM using demand paging
  • Page Fault – Page not in RAM; OS loads from disk (heavy overhead)
  • Thrashing – Too many page faults; CPU busy with swapping

Page Replacement Algorithms

FIFO Replace oldest loaded page. Simple. Susceptible to Belady's anomaly.
LRU Replace least recently used. Near-optimal. Needs timestamp/stack.
Optimal Replace page used farthest in future. Theoretical benchmark only.

Key Formulas

EAT = α(TLB+Mem) + (1−α)(TLB+2×Mem)  // α=hit ratio
EAT (PF) = (1−p)×mem + p×page_fault_time  // p=fault rate
Phys Addr = Frame# × PageSize + Offset
Unit IV — File Systems & Disk

File Allocation Methods

MethodAccessProsCons
ContiguousSequential + RandomFast readExternal frag, hard to grow
LinkedSequential onlyNo ext fragSlow random; pointer overhead
IndexedDirect + RandomNo ext fragIndex block overhead

Directory Structures

  • Single-Level – All files in one dir; naming conflicts
  • Two-Level – Separate dir per user; no sharing
  • Tree-Structured – Hierarchical; paths; most common (Unix/Windows)
  • Acyclic Graph – Shared files via links/aliases

Free Space Management

  • Bitmap – 1 bit per block; efficient but large for big disks
  • Linked List – Free blocks chained; no waste but slow traversal
  • Grouping – Store n free blocks in first free block; faster

Disk Scheduling Algorithms

AlgorithmStrategyBest When
FCFSServe in arrival orderLight load; fairness needed
SSTFNearest cylinder firstHeavy load; may starve far requests
SCANSweep back & forth (elevator)Mixed load; no starvation
C-SCANOne direction only; jump backUniform wait times
Total Movement = Σ |curr_head − next_request|  // sum of all seeks

Banker's Algorithm (Avoidance)

  • Need Matrix = Max − Allocation
  • Grant request only if system stays in safe state (safe sequence exists)
  • Safe state → deadlock free; Unsafe → possible deadlock
⚡ Most Frequently Tested Questions (from QB + Sample Papers)
U-I: Scheduling Numericals Draw Gantt charts & compute avg WT/TAT for SJF, RR (quantum=1 or 2), FCFS, and Priority — with given arrival & burst times. Most repeated GATE questions.
U-I: Preemptive vs Non-Preemptive Examine effects of preemptive vs non-preemptive scheduling on process states. Compare SRTF and FCFS for given process snapshots.
U-II: Banker's Algorithm Given Allocation & Max matrices + Available: calculate Need matrix. Determine if P2's resource request can be safely granted (safe sequence check).
U-II: Deadlock Detection Identify if pseudocode (P1:lock R1,R2; P2:lock R2,R3; P3:lock R3,R1) results in deadlock. Design deadlock-free version using prevention technique.
U-III: Page Replacement Apply LRU, FIFO, OPT to reference string (e.g. 7,0,1,2,0,3,0,4,2,3…) with 3 frames. Count page faults for each. Show all steps clearly.
U-III: TLB / EAT Calculation Given TLB access time (25ns), memory time (150ns), hit ratio (85%) — calculate Effective Access Time. Also: page fault EAT with disk access time.
U-IV: Disk Scheduling Given request queue + initial head position — compute total cylinder movement for FCFS, SSTF, SCAN, and C-SCAN. Compare and justify best algorithm for scenario.
U-IV: File Allocation & Free Space Compare contiguous, linked, indexed file allocation. Calculate internal fragmentation (linked allocation with pointer overhead). Bitmap vs. linked list free space tracking.
