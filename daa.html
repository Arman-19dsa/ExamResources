⬡ Divide & Conquer
Steps: Divide → Conquer → Combine
Binary Search

Recurrence: T(n)=T(n/2)+C → O(log n)

Best:O(1) mid hit · Worst:O(log n) absent

Merge Sort

Recurrence: T(n)=2T(n/2)+n → O(n log n)

Stable · Always O(n log n) · O(n) space

Quick Sort

Pivot partitions array · Last/random pivot

Worst when sorted · Avg O(n log n) · O(log n) space

Karatsuba Multiplication
X·Y = ac·10²ᵐ + (ad+bc)·10ᵐ + bd

ad+bc = (a+b)(c+d)−ac−bd → only 3 recursive calls

Recurrence: T(n)=3T(n/2)+O(n) → O(n^1.585)

⬡ Greedy Strategy

Locally optimal choice at each step → globally optimal (when applicable)

Fractional Knapsack

Sort by profit/weight ratio ↓ · Take fractionally

O(n log n) · Optimal for fractional, NOT 0/1

Job Scheduling

Sort by profit ↓ · Schedule in latest available slot before deadline

O(n log n) sort + O(n²) scheduling

Dijkstra's Algorithm

Single-source shortest path · Non-negative weights only

Priority queue + greedy relaxation → O(E log V)

Use Bellman-Ford O(VE) for negative weights / cycle detection

MST Algorithms
Prim's Grows tree from vertex · Dense graphs · O(E log V)
Kruskal's Sort edges, add min no-cycle · Sparse graphs · O(E log E)
⬡ Dynamic Programming

Solve once, store results — avoid recomputation (overlapping subproblems + optimal substructure)

0/1 Knapsack — DP Table
dp[i][w] = max(dp[i-1][w], val[i]+dp[i-1][w-wt[i]])

Time: O(nW) · Space: O(nW) or O(W) optimized

Floyd-Warshall (All-Pairs Shortest Path)
dist[i][j] = min(dist[i][j], dist[i][k]+dist[k][j])

Time: O(V³) · Works with negative edges (no neg cycles)

Binomial Coefficient
C(n,k) = C(n-1,k-1) + C(n-1,k)
Sum of Subset · Multistage Graphs

Sum of Subset: dp[i][s] = dp[i-1][s] || dp[i-1][s-a[i]]

Multistage: Shortest path with stages, forward/backward DP

Memoization vs Tabulation
Top-Down Recursive + memo cache · natural, lazy
Bottom-Up Iterative table · no stack overflow · faster
⬡ Backtracking

DFS + prune infeasible paths → explore all valid solutions

8-Queens Problem

Place N queens so no two share row/col/diagonal

Check: col[j], diag1[i-j], diag2[i+j]

92 solutions for N=8 · Worst: O(n!)

Graph Coloring

Assign colors so no adjacent vertices share color

Try color c for vertex v → recurse → backtrack if conflict

Chromatic number χ(G) · Time: O(m^V)

0/1 Knapsack via Backtracking

State-space tree · include/exclude each item

Prune: weight > capacity or bound < best

Upper bound: current + greedy fill of remaining

Control Abstraction

BT(x[1..k]) → if(feasible) → BT(x[1..k+1])

Bounding fn prunes; answer node = complete solution

⬡ Branch & Bound

Pruning using cost bounds for optimization — better than backtracking for min/max problems

Three Strategies
FIFO Queue (BFS style) · explores breadth-first
LIFO Stack (DFS style) · less memory but may be slow
LC (Best-First) Priority queue · explore node with best bound first
0/1 Knapsack — B&B

Upper bound at node = current profit + greedy(remaining)

Prune if UB ≤ best known · O(2ⁿ) worst but much better avg

TSP — Branch & Bound

Lower bound via row/column reduction of cost matrix

Explore cities, prune paths with LB ≥ current best tour

Reduced cost matrix → LB = sum of reduction constants
BT vs B&B
Backtracking → feasibility · combinatorial problems
Branch & Bound → optimality · uses cost bounds
⬡ P, NP & Key Recurrences
Complexity Classes
P Solvable in poly time — Sorting, Shortest Path
NP Verifiable in poly time — SAT, Knapsack
NP-Hard At least as hard as NP — TSP, Halting Problem
NP-Complete NP ∩ NP-Hard — 3-SAT, Hamiltonian Cycle

P ⊆ NP · NP-Complete ⊆ NP-Hard · P=NP? (unsolved)

Key Recurrences
T(n)=T(n/2)+1→ O(log n) · Binary Search
T(n)=2T(n/2)+n→ O(n log n) · Merge Sort
T(n)=T(n-1)+C→ O(n) · Factorial, Tree
T(n)=2T(n-1)+1→ O(2ⁿ) · Tower of Hanoi
T(n)=T(n-1)+T(n-2)→ O(2ⁿ) naive · O(n) DP
