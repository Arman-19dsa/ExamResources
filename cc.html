Deployment Models

  • Public – Owned by provider; open to all. AWS, Azure, GCP
  • Private – Dedicated to one org; on-prem or hosted
  • Hybrid – Mix of public + private; burst traffic use-case
  • Community – Shared among similar orgs (govt, healthcare)

5 Key Characteristics (NIST)

On-demand Self-service Broad Network Access Resource Pooling Rapid Elasticity Measured Service

Virtualization Concepts

  • Hypervisor Type 1 – Bare-metal (VMware ESXi, Hyper-V)
  • Hypervisor Type 2 – Hosted on OS (VirtualBox, VMware WS)
  • vSphere – VMware's full virtualization platform suite
  • Machine Image – Snapshot of VM state (AMI in AWS)
  • Load Balancing – Distribute traffic across VMs for HA & perf
  • Capacity Planning – Predict & scale resources proactively

Containerization

  • Docker – Container engine; image + runtime
  • Dockerfile – Blueprint for container image
  • Image → Container (run-time instance)
  • Kubernetes (K8s) – Container orchestration
  • Pod – Smallest K8s unit (1+ containers)
  • Service – Stable endpoint for pods
Unit II — AWS & Web Services

Core AWS Services

  • EC2 – Virtual servers; configurable CPU, RAM, OS
  • AMI – Pre-configured disk image for EC2
  • S3 – Object storage; buckets & keys; 99.999…% durable
  • EBS – Block storage attached to EC2 instances
  • EFS – Scalable file system for multi-EC2 access
  • Elastic Load Balancer – ALB / NLB for traffic distribution
  • Auto Scaling – Add/remove EC2s based on metrics
  • VPC – Isolated virtual network in AWS
  • IAM – Identity & access management (users, roles)
  • CloudWatch – Monitoring, logs & alarms
  • Route 53 – DNS & routing (failover, latency-based)

EC2 Key Concepts

  • Instance Types – t2/t3 (general), c-series (compute), r-series (memory)
  • Pricing – On-demand | Reserved | Spot | Dedicated
  • Security Groups – Stateful firewall at instance level
  • Key Pairs – SSH access using .pem files

AWS Regions & AZs

  • Region – Geographic area with 2+ AZs (e.g., ap-south-1)
  • AZ – Isolated data center within a region
  • Multi-AZ – Deploy across AZs for fault tolerance

Scalability Techniques

  • Sharding – Horizontal split of data across nodes (partition key)
  • Replication – Copy data to replicas (read scaling + HA)
  • Multi-AZ – Synchronous standby for automatic failover
  • Read Replicas – Async copies for read-heavy workloads
  • Caching – Write-through / Write-back with Redis/Memcached

DB Choice by Use-Case

  • Banking / ERP → Relational (ACID)
  • Session / Cart → Key-Value (DynamoDB)
  • Social / CMS → Document (MongoDB)
  • Fraud Detection → Graph (Neo4j)
  • IoT / Metrics → Time-Series
  • Leaderboard / Cache → In-Memory (Redis)
Unit IV — Security in Cloud

CIA Triad

Confidentiality Encryption, IAM, ACLs. Only authorized access.
Integrity Hashing, checksums. Data unchanged in transit.
Availability Multi-AZ, redundancy. 99.9%+ uptime SLA.

Types of Cloud Risks

  • Data Breach – Unauthorized data access / exfiltration
  • Insecure APIs – Weak auth on management interfaces
  • Insider Threat – Malicious/negligent privileged users
  • Shared Tech Vuln – Hypervisor or shared infra exploits
  • Account Hijack – Phishing, credential theft
  • DDoS – Overload services to cause outages

Security Mechanisms

  • Encryption – AES-256 at-rest; TLS 1.3 in-transit
  • IAM / RBAC – Least privilege; role-based access
  • MFA – Multi-factor authentication on accounts
  • Key Mgmt (KMS) – Managed keys for encryption
  • WAF – Web App Firewall; block SQLi, XSS
  • VPC Security Groups – Stateful port-level firewall
  • NACLs – Stateless subnet-level access control
  • CloudTrail – Audit logs of all API calls

HA & Scalability

  • H. Scaling – Add more instances (scale-out)
  • V. Scaling – Bigger instance (scale-up); has limit
  • Auto Scaling – Trigger on CPU/RAM/latency metrics
  • CDN – Edge caching (CloudFront) for global latency
